# A score knows which model produced it, and the curve refuses when it changed

## Scale classification

**L2 — Feature.** One capability (`evals`), one component
(`apps/api/secondshift/evals/`), under a day. It changes a public signature —
`EvalRunner.score`'s `generate` callable — and adds a refusal to a command whose
refusals are themselves a specified requirement, so it needs a proposal and a
spec delta rather than tasks alone. No new system, no migration: the column this
fills has existed since `0001_initial.sql`.

## Why

**`eval_results.model_call_id` has never been written.** The column exists in
the base schema, its comment explains what it is for, and
`EvalRunner._record_result`'s `INSERT` omits it. Nothing records which model
produced the output a score was given for.

That is not a tidiness problem, because of what the curve does next. The
comparison refuses six ways — different rubrics, different judges, an incomplete
run, a synthetic run, different prompt sets, and the same brain state on both
sides — and every one of those exists to stop a number meaning something other
than it looks like. **A week 1 generated by the local reasoner and a week 8
generated in the cloud is not among them.** The curve would report that
difference as the brain having learned, and the submission's centerpiece is
exactly that number.

The shortest path to the week-8 result is the path that breaks it. Week 8 opens
on 15 Oct, the week-1 baseline is still `awaiting-scoring`, and both runs have
to be generated before either can be scored. Generating them in two different
sessions against two different providers is the obvious way to spend the time
available, and nothing in the system would notice.

**The seam that loses the identity is one parameter.** `score(..., generate=...)`
takes a callable returning `str`. The provider layer already returns
`Completion`, which carries `model_call_id` — `providers/base.py` built that
specifically so "a caller receives the recorded call's id." The eval runner is
the one caller that throws it away.

**And the scoring path has no entry point** — deliberately, which is worth
knowing before reaching for it. `python -m secondshift.evals` offers `seed`,
`activate`, `baseline`, `summarize`, `status` and `curve`, and that module's
docstring says scoring is "deliberately absent from this entry point until a
judge is chosen and a generating provider is configured." That was right: the
baseline needs neither, which is why the two are separable at all.

It stops being right the moment a judge exists, and `EvalRunner.score` is
meanwhile called from nowhere but `apps/api/tests/test_evals.py` — the method
that produces the submission's number, reachable only from the test suite.
**The command belongs with the judge, not here.** Added now it could only
refuse, which is the same unreachable shape wearing a different costume; added
with the judge, the entry point and the thing it calls arrive together. It is
recorded here because this is the change that went looking.

## What this change is not

- **Not a judge, and not the `score` command.** No implementation of the `Judge`
  protocol calls a model, and this change does not add one. The command that
  would call it goes with it, for the reason given above.
- **Not a migration.** `model_call_id` and `output_path` are already columns.
- **Not a change to the threshold.** `config/evals/threshold.md` is fixed, and
  its hash is in the history. Nothing here touches what the bar is.
- **Not a new refusal policy for within-run mixtures.** A run whose samples came
  from two models is a muddle, but it is not the failure this guards against,
  and inventing a rule for it here would be deciding something nobody has asked.

## What changes

1. **`generate` returns `Completion`, not `str`.** The runner reads `.text` for
   the judge and `.model_call_id` for the row. A callable that returns bare text
   is refused with a message naming the parameter, rather than being coerced —
   coercion would reintroduce the unrecorded case silently.

2. **`_record_result` writes `model_call_id`.** The column stops being
   decorative.

3. **`RunSummary` carries `generators`** — the distinct `model_calls.model`
   values behind a run's results, read through `model_call_id`.

4. **The curve refuses two more ways**, both under the existing requirement
   about comparisons that would mean something:
   - either run does not record which model produced its outputs, because a
     guard that cannot see one side is not a guard;
   - the two runs' outputs came from different models, because then the
     difference is the model and not the brain.

5. **Three documents stop disagreeing about the refusal count.**
   `docs/SPEC_ROADMAP.md` says the curve "refuses five ways",
   `docs/SUBMISSION.md` says six, and the code has six conditions across seven
   raise sites. After this change there are eight, and every figure that states
   it derives from the code.

## Impact

- `apps/api/secondshift/evals/runner.py` — the `generate` contract,
  `_record_result`, `RunSummary`, two refusals in `curve`.
- `apps/api/secondshift/evals/__main__.py` — `summarize` prints what produced a
  run.
- `apps/api/tests/test_evals.py` — every `score(...)` call site passes a
  callable returning `Completion`. **This is a contract change and those tests
  change with it**, which is the cost of the fix and is stated rather than
  hidden.
- `scripts/check-mutations.py` — one mutation for the new guard.
- `docs/SPEC_ROADMAP.md`, `docs/SUBMISSION.md` — the refusal count.

## Constitution Compliance

- **Principle 1 (the brain is plaintext under git).** Untouched. Generation
  still reads the brain at the recorded commit.
- **Principle 2 (Privacy Airlock).** Untouched, and slightly strengthened: the
  provider that produced an eval output becomes recorded, so an output generated
  through a cloud provider is visible as such instead of indistinguishable from
  a local one. No new egress; nothing new leaves the machine.
- **Principle 3 (no empty mornings).** Not in the night path.
- **Principle 4 (text-first).** No interaction surface.
- **Principle 5 (one codebase, two deployments).** Nothing branches on which
  instance is running. `is_synthetic` stays server-derived, and the curve's
  existing exclusion of synthetic runs is untouched.
- **Principle 6 (scope boundary).** Inside `evals`, which is how the learning
  claim is measured rather than a new capability.
- **Principle 7 (telemetry from line one).** This is the principle the change
  serves, and also the one it is late for. A model call whose row exists but is
  unreferenced by the score it produced is telemetry that cannot answer the one
  question it was recorded for. The principle says instrumentation must not be
  retrofitted because the gap cannot be backfilled — and this is a retrofit. It
  costs nothing only because the gap is zero rows wide: the single real eval run
  reads `judge_model = 'awaiting-scoring'` and has no results. Done after the
  first run is scored, it would be unfixable for exactly the comparison the
  system exists to report. No new model call is introduced, so no new row is
  owed.

## Risk

**The test suite changes.** Nineteen call sites in `test_evals.py` pass
`generate=`, and all of them move to returning `Completion`. A refactor that
rewrites its own tests is a refactor that can quietly stop asserting, so the
mutation is the control: the guard must be shown to fail with the fix removed,
not merely observed to pass.

**A stricter curve could refuse the real comparison.** If the week-1 and week-8
runs are generated through different providers, this change turns the submission's
headline number into a refusal. That is the intent — the refusal is correct and
the number would not have been — but it means the generation plan has to be
decided before 15 Oct rather than discovered on 21 Oct.
